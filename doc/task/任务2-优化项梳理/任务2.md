# AI分析的待改进项

结论：当前最大的体验短板不是视觉样式，而是“操作后发生了什么”缺少反馈。知乎助手最值得借鉴的也是状态闭环，而不是照搬配色和布局。

我实际打开本地页面巡检过，确认了首屏留白较多、主次操作混在一起、管理页空态弱、日志页只有原始文本等问题。本轮仅做审计，没有修改代码。

## 第一优先级：体验闭环

1. 备份任务增加完整运行状态

目前点击“开始备份”后立即切换日志页，并一直等待整个 workflow；按钮没有 loading、防重复、成功、部分成功或失败反馈。[customer_task/index.tsx](D:/win_www/stablog/client/src/pages/customer_task/index.tsx:678)

建议：

- 按钮显示“正在启动/备份中”并禁止重复点击。
- 显示 `初始化 → 抓取 → 生成`阶段状态、运行时长和 runId。
- 明确区分成功、部分成功、失败、已有任务运行中。
- 完成后提供“打开输出目录”“重试失败项”。
- 长期将 IPC 改为立即返回 runId，前端订阅运行状态。

主进程已经返回 `status/runId/stages`，第一版主要是把现有结果消费起来。[ipc_handlers.ts](D:/win_www/stablog/src/interface/electron/ipc_handlers.ts:341)

2. 所有异步操作统一反馈

同步用户、导入导出、刷新数据、检查更新、打开目录等，大量路径缺少 `try/catch/finally`。失败后可能永久 loading，或者表现为“按钮没反应”。[manage/index.tsx](D:/win_www/stablog/client/src/pages/manage/index.tsx:64)

建议引入统一 action 封装：

- loading
- 成功 message
- 失败 message/Alert
- 可复制的错误码
- finally 恢复按钮
- 可重试操作

知乎助手的数据页已经采用这套模式。[db_explorer/index.tsx](D:/win_www/zhihuhelp/client/src/page/home/component/db_explorer/index.tsx:117)

3. 增加页面异常兜底

当前 React 直接渲染，组件异常会整页白屏。[main.tsx](D:/win_www/stablog/client/src/main.tsx:1)

建议参考知乎助手的 Error Boundary，提供：

- “页面加载失败”
- 重新加载
- 打开运行日志
- 导出诊断信息

参考实现：[frontend_error_boundary.tsx](D:/win_www/zhihuhelp/client/src/library/frontend_error_boundary.tsx:13)

4. 首次启动失败要能被用户看见

现在初始化发生在创建窗口之前；初始化失败只记录日志后退出。用户看到的是软件没有启动。[application_bootstrap.ts](D:/win_www/stablog/src/application/bootstrap/application_bootstrap.ts:45)

建议分两步：

- 近期：弹出原生错误框，显示原因、日志位置和“打开日志目录”。
- 后续：配置、数据库、日志迁到 `app.getPath('userData')`，避免安装目录只读导致启动失败。

5. 修正配置初始化与自动保存体验

当前读取配置、登录检测和同步用户并行启动，存在用空主页先同步的可能；配置变化还会立即异步写盘，没有“保存中/已保存/失败”状态。[customer_task/index.tsx](D:/win_www/stablog/client/src/pages/customer_task/index.tsx:158)

建议：

- 配置加载完成后再检查登录和同步用户。
- 自动保存增加 300–500ms 防抖并串行写入。
- 显示“保存中 / 已保存 / 保存失败”。
- 启动任务前强制 flush 最新配置。
- 保留当前“损坏配置不自动覆盖”的安全机制，这一点比知乎助手更稳妥。

## 第二优先级：重新组织主流程

`登录微博 → 粘贴个人主页 → 同步识别 → 选择范围 → 开始备份 → 查看结果`

具体调整：

- 增加四步快速开始卡片。
- 用户信息、耗时和失败记录改成紧凑摘要卡。
- “退出账号”放入账户菜单。
- “打开调试面板”和开发配置仅在 debug 模式显示。
- 主操作按钮独立突出，不与检查更新、退出账号并列。

知乎助手可参考的部分是快速步骤和登录状态提示：[customer_task/index.tsx](D:/win_www/zhihuhelp/client/src/page/home/component/customer_task/index.tsx:488)

## 第三优先级：日志与数据管理

日志页建议从原始文本升级为运行仪表盘：

- 当前任务状态及阶段标签
- 最近事件
- 本会话错误
- 成功/失败/部分成功结果
- 输出历史与“打开文件夹”
- 仅查看错误、复制错误、导出诊断
- 原始日志放到底部并虚拟滚动

当前页面每秒读取日志、强制滚到底部，并可能由前端截断日志文件，不利于排错。[log/index.tsx](D:/win_www/stablog/client/src/pages/log/index.tsx:18)

知乎助手的阶段、本会话错误和输出历史很适合作为参考：[log/index.tsx](D:/win_www/zhihuhelp/client/src/page/home/component/log/index.tsx:470)
