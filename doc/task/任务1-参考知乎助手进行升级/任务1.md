## 升级范围

稳部落本次升级仅对齐通用工程基础，产品能力按阶段另行选择，不默认移植知乎助手 3.0.0 的全部功能。

通用工程能力包括如下部分
- 开发环境升级至以下
  - Node.js 24、pnpm 11、Electron 43
  - babel编译产物输出为原生 ESM (特殊的必须使用cjs的部分可以例外)
- 主进程/CLI/GUI 复用 workflow
- 统一 schema
- 支持记录错误
- 调整架构，使之解除耦合，可以进行单测
- 梳理现有链路，标注服务等级
- 针对链路
  - 铺设结构化日志，目标是可以根据日志和源码，直接定位到故障位置与原因
  - 添加单元测试、离线集成测试。关键业务路径和失败路径均有测试
- 补齐架构、数据、IPC、日志、测试、发布和故障排查文档

产品功能至少增加以下部分

- 支持输出markdown
- 支持导出全量json，增量导入json。导入时同 ID 数据按业务更新时间保留较新版本
- 由于涉及导出markdown，需要将协议切换至 MIT/GPL 双许可
- 需要基于vitepress初始化官网，描述功能

## 第一阶段：工程基线与可测试架构

第一阶段完成以下内容：

- 将运行时和开发环境升级至 Node.js 24、pnpm 11、Electron 43，并将 Babel 编译产物迁移至原生 ESM；确有运行时限制的边界可保留为 CommonJS。
- 保持 `pnpm start` 只启动已有的 `dist/index.js`，开发期间由 `pnpm watch` 独立更新 `dist`。
- 建立主进程、CLI、GUI 可共同复用的 workflow 骨架和隔离的运行上下文，为后续业务迁移提供稳定边界。
- 统一任务配置、IPC 请求/响应、workflow 执行结果、结构化错误和日志事件的 schema。
- 数据库实体 schema 在第一阶段继续由模型和迁移定义，不为统一导出格式而重构；后续阶段允许按最终目标重建现有数据库及表结构，无需兼容历史数据库。
- 建立测试框架和隔离测试基座，确保测试不读取或覆盖现有业务配置、缓存、数据库、日志和输出目录。
- 梳理现有业务链路并标注重要度/可用性等级：S0 为应用无法启动或数据损坏，S1 为核心抓取或生成不可用，S2 为部分任务或非核心能力失败，S3 为体验或诊断问题。为各等级规定错误码、结构化日志字段、测试覆盖和故障处理说明。
- 第一阶段不实现 Markdown、JSON 导入导出和官网，这些能力在后续阶段实施。
