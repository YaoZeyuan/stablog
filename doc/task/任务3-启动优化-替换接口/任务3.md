# 任务3：启动优化与日期检索接口替换

## 目标

旧版接口只能先获取微博总数，再按全局页码分页；发布新微博后旧页码会漂移，也无法可靠恢复失败任务。本任务改用微博日期检索接口，从稳定日期范围规划、抓取和恢复任务，同时保持现有 SQLite 数据与 HTML/PDF 输出能力。

接口请求、响应示例和 Markdown 样式见[微博接口说明](../任务2-优化项梳理/微博接口说明/微博接口说明.md)。

## 接口与数据模型

- 日期检索使用 `GET https://weibo.com/ajax/statuses/searchProfile`，传入目标 UID、北京时间起止秒、从 1 开始的页码以及全部内容类型开关。每页最多返回 50 条当前登录用户有权阅读的微博。
- 用户信息和长微博分别使用接口说明中的 `ajax/profile/info` 与 `ajax/statuses/longtext`；微博文章继续使用现有文章详情能力。
- 所有新接口响应必须先通过 zod 运行时校验，再进入业务逻辑。只消费的必要字段严格校验，未消费的新增字段允许透传。
- 检索成功必须满足 `ok: 1`、`data.list` 为不超过 50 项的数组，且 `data.total` 为非负安全整数或纯数字字符串；业务层统一将 `total` 归一化为 `number`。成功空结果必须为 `list: []` 且 `total: 0`。其他 HTTP、业务或 schema 响应均视为失败，不得当作空结果。
- 新接口 DTO 先转换为稳定的内部微博模型，再写入 SQLite 和交给 HTML/PDF 生成器；输出层不得依赖供应商响应结构。转换覆盖原帖、转发、图片、视频、文章、普通长文和 Markdown 长文。Markdown 转换为 HTML 并使用接口说明提供的 `.markdown-body` 样式。
- 接口失败诊断必须脱敏，不记录 Cookie、token、完整响应正文或其他凭证。

## 日期规划

- 默认抓取范围为北京时间 `2009-09-01` 至任务启动日 `23:59:59`，允许用户选择起止日期；开始日期不得早于 `2009-09-01`，结束日期不得晚于任务启动日。
- 新批次在创建时冻结任务启动日和完整配置；之后继续同一批次时不自动扩大到新的当天。
- 先按年检索一次；年度总数为 0 时将该年度标记成功并剪枝，否则创建当年的月任务。
- 月任务总数为 0 时标记成功并剪枝，否则创建与用户范围相交的固定日期段：`1~7`、`8~14`、`15~21`、`22~28`、`29~月末`。所有范围均为北京时间闭区间且不得跨月。
- 日期段总数为 0 时标记成功并剪枝；大于 0 时创建 `1..ceil(total/50)` 的页任务。当前启动日所在日期段不使用旧缓存，以便下次新批次获取新增微博。
- 当前日以 `23:59:59` 为范围终点；运行期间新增微博仍可能导致该日期段发生分页漂移。数据库按微博 ID 幂等写入以去重，下次新批次会重新抓取该日期段。

## 可恢复任务与重试

- SQLite 持久化任务批次、目标用户和年/月/日期段/页任务。任务状态为 `pending`、`running`、`succeeded`、`failed`；批次额外聚合 `partial_success`。
- 应用启动时将遗留的 `running` 任务转为可重试的 `failed`。恢复不自动执行，由用户在 GUI 中手工继续。
- 同一时刻只运行一个备份流程；批次内多个用户按配置顺序处理，所有用户共享全局限流器。
- “继续任务”复用原批次、冻结配置和截止日，跳过已成功任务，重新执行失败和未完成任务。
- `isSkipFetch=true` 的新批次以及抓取任务已全部成功、仅重新执行失败生成阶段的旧批次均可离线运行：不得要求有效 Cookie、查询登录 UID 或创建微博 API client。离线新批次使用明确的内部离线身份；旧批次继续沿用其冻结的 `loginUid`。只要仍有 `pending`、`running` 或 `failed` 抓取任务，就必须校验当前微博登录身份与批次身份一致。
- “重新抓取”创建新批次，不复用旧批次成功状态；微博数据继续按 ID upsert，是否读取 HTTP 缓存由新批次缓存策略决定。
- 支持重试单个失败任务及全部失败任务。检索页成功后保存微博；长文或文章补全失败必须保留可重试状态，不得把失败伪装为成功。
- 抓取部分失败时 workflow 返回 `partial_success`，允许使用已成功数据继续生成输出，并在 GUI 保留失败任务供后续重试；无法规划、鉴权失败或数据库失败等全局错误返回 `failure`。
- 不提供暂停或取消。重复点击开始、继续或重试时返回当前活动批次，不创建第二个流程。

## HTTP JSON 缓存

- 缓存位于 `Path.cachePath` 下的独立微博 HTTP 缓存目录，按登录 UID、目标 UID、接口版本和规范化请求参数隔离；缓存内容不得包含 Cookie 或 token。
- 只有请求范围结束时间严格早于批次启动时刻减一个自然月、且不属于启动日所在日期段时，才允许缓存通过 schema 校验的成功响应。缓存不设有效期。
- “优先使用缓存”会读取有效缓存并缓存 miss；“忽略缓存并刷新”跳过读取，成功后覆盖可缓存响应。损坏或 schema 不匹配的缓存按 miss 处理并在成功请求后替换。
- GUI 可清除当前登录身份下指定目标用户的微博 HTTP JSON 缓存；不得删除其他用户缓存、图片/HTML 缓存、微博 SQLite 数据或任务历史。

## 全局限流与预计时间

- 用户信息、日期检索、长微博、文章和失败重试等微博抓取 API 的实际网络请求共用主进程全局限流器；缓存命中不占用网络请求时隙。
- 相邻网络请求的开始时间至少间隔配置值，默认且最小为 10 秒。失败请求同样占用时隙，不增加额外退避；失败任务由人工继续或重试。
- 启动前用用户微博数、日期跨度和请求间隔给出粗略预计时间；任务规划过程中动态修正总请求数与预计剩余时间，计算基础为剩余请求间隔并乘以 `1.5` 预留渲染时间。

## 配置与 GUI

- 不兼容旧任务配置。移除 `fetchStartAtPageNo`、`fetchEndAtPageNo` 和 `onlyRetry`，改为抓取日期范围、缓存读取策略和请求间隔；输出日期范围仍独立配置。
- GUI 支持多个目标用户配置并按顺序处理。活动任务期间禁止修改配置、清缓存、退出登录或重复启动。
- GUI 新建跳过抓取任务时不检查微博登录状态，只允许使用已保存的数字 UID、直接输入的数字 UID，或可在本地解析出数字 UID 的微博主页地址；需要跳转或接口查询的昵称地址仍须先改为直接 UID，不能在离线分支发起解析请求。
- 配置页和日志页展示同一份持久化进度：批次阶段、当前用户/年/月/日期段/页、成功/失败/待处理数量、缓存命中数及预计剩余时间。
- GUI 展示脱敏失败任务列表，支持单项重试、全部重试和继续未完成批次；新建批次与继续批次必须明确区分。
- 任务启动采用立即回执，主进程后台执行，renderer 通过受控 IPC 轮询 SQLite 快照；清空日志不得影响任务进度。

## 兼容与验收边界

- 继续复用现有 `total_mblog`、`total_user` 与 HTML/PDF 输出链路；新任务表采用增量 `CREATE TABLE IF NOT EXISTS`，不得删除或覆盖现有业务数据库和微博记录。旧 `fetch_error_record` 可保留但不再作为新流程真相源。
- GUI 与 CLI 继续共用 application workflow；`pnpm start` 只启动已有 `dist/index.js`，开发构建由 `pnpm watch` 或构建命令完成。
- 所有自动化测试必须使用临时配置、SQLite、缓存、日志和输出目录以及 fake transport/clock，不得访问网络或读取、覆盖现有业务数据。
- 完成时同步更新 `doc/dev` 中的架构、数据、IPC、日志和测试说明，并运行匹配范围的类型检查、单元测试、集成测试和构建。

## 日志架构

- 后端日志真正迁移到 Winston，输出到 `log/runtime-YYYY-MM-DD.log`；前端日志通过受控 IPC 交给主进程写入独立的 `log/frontend-YYYY-MM-DD.log`。日志文件使用一致的结构化格式和日期命名，不再把手写 `fs.appendFileSync` 作为日志实现。
- 跨越 renderer/主进程 IPC、HTTP、缓存、数据库、文件系统、渲染与外部命令等系统边界时，记录请求开始及成功、部分成功、跳过或失败结果；根据排障价值使用 debug/info/warn/error 等不同等级，并记录操作名、耗时、traceId/runId 和脱敏错误链。
- HTTP 日志记录 method、脱敏 URL 路径和参数摘要、状态码或业务状态，以及响应类型、数量和必要业务标识等结构摘要。其他边界同样只记录排障所需的请求与结果摘要。
- 所有日志继续递归脱敏并限制体积；禁止记录 Cookie、Authorization、token、请求/响应 headers、完整正文、HTML 和原始 JSON。
