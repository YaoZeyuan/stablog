# 开发说明

本说明对应第一阶段工程基线。详细设计见 [开发文档索引](./dev/README.md)。

## 环境

- Node.js 24（见根目录 `.node-version` / `.nvmrc`）
- pnpm 11.5，必须从仓库根目录安装依赖
- Electron 43.3

```powershell
corepack enable
pnpm install --frozen-lockfile
```

根 `pnpm-lock.yaml` 同时管理主程序和 `client`，不要在 `client` 内生成独立锁文件。

## 开发命令

```powershell
pnpm watch
pnpm start-client
pnpm start
```

三个命令分别运行。`pnpm watch` 只持续编译 `src` 到 `dist`；`pnpm start-client` 启动前端开发服务器；`pnpm start` 只启动已有的 `dist/index.js`，不会隐式编译。

CLI 使用 Optique，只负责参数解析，业务统一进入 application workflow：

```powershell
pnpm build-server
pnpm cli --help
pnpm cli init --config customer_task_config.json
pnpm cli fetch --config customer_task_config.json
```

旧 PDF 生成器仍依赖 Electron `BrowserWindow`，所以 CLI 的 `generate` / `run` 会返回明确的 `GENERATE_FAILED`；完整生成流程从 GUI 启动。

## 提交前验收

```powershell
pnpm tsc
pnpm test
pnpm build-dist
pnpm debug-build
```

`pnpm debug-build` 在 `release/win-unpacked` 生成 Windows 目录包。测试使用系统临时目录并启用离线网络守卫，不得指向仓库现有配置、数据库、缓存、日志或输出目录。

## 代码边界

- 根包是原生 ESM；内部相对/别名 import 必须写 `.js` 扩展名。
- 仅明确的 CommonJS 边界使用 `.cjs`：preload、构建脚本和 vendored jsPDF。
- GUI、CLI 和旧 `DispatchTaskCommand` 必须调用 `RunTaskWorkflow`，不得复制 init/fetch/generate 编排。
- IPC 使用 preload 白名单和 `invoke/handle`，请求与响应必须经过 schema/结果信封。
- 旧抓取/生成实现通过全局路径兼容桥的进程内队列串行运行；新代码不得继续增加静态路径依赖。

## 包选型

同类能力优先采用知乎助手已经验证的版本：Node 24、pnpm 11.5、Electron 43.3、Babel 8、TypeScript 7、Optique 1.2、Vitest 4。稳部落额外直接声明 Vite 8.2，是为了避免 Umi 工作区带入 Vite 4 后破坏 Vitest 4 的运行时导出；前端继续使用现有 Umi 构建链。

电子书封面尺寸仍为 100 × 130（宽 × 高）。
